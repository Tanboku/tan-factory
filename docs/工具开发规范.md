# 兔子工厂 · 新工具开发规范

> 适用版本：v1.0.0
> 本文档面向要为「兔子工厂」新增工具的开发者，所有约定与项目内已实现的架构一一对应。

---

## 1. 工具系统架构总览

兔子工厂采用 **「自动发现 + 统一协议」** 的插件化架构，一个工具由至多三部分组成：

```
src/renderer/src/tools/<tool-id>/     ← ① 前端（必需）
    manifest.js                          工具清单：元数据 + 懒加载入口
    Panel.jsx                            工具界面（React 组件）

src/main/services/<tool-id>.js        ← ② 后端（可选，仅需要系统能力时）
                                          导出 { id, run(action, payload, ctx) }
```

两条自动发现链路，**均无需修改任何注册代码**：

| 链路 | 机制 | 说明 |
| --- | --- | --- |
| 前端 | `core/registry.js` 用 `import.meta.glob('../tools/*/manifest.js')` 扫描 | 面板自动出现新工具卡片，每个工具独立代码分包（构建产物中为单独的 `Panel-*.js` chunk） |
| 后端 | `main/services/index.js` 用 `fs.readdirSync` 扫描本目录 | 统一经 IPC `tool:run` 调用，错误自动捕获并包装为 `{ ok: false, error }` |

前后端通过 **统一 IPC 协议** 通信：

```js
// 渲染进程任意位置
const res = await window.api.tool.run(toolId, action, payload);
// res: { ok: true, data } 或 { ok: false, error: string }
```

## 2. 快速开始：最小可用的纯前端工具

**第一步**，新建目录 `src/renderer/src/tools/hello/manifest.js`：

```js
export default {
  id: 'hello',
  name: '你好世界',
  desc: '示例工具',
  icon: '👋',
  category: 'work',
  keywords: ['hello', '示例'],
  load: () => import('./Panel.jsx'),
};
```

**第二步**，同目录新建 `Panel.jsx`：

```jsx
import React from 'react';

export default function HelloPanel() {
  return (
    <div className="ic-panel">
      <div className="empty-state small">
        <span className="empty-face">👋</span>
        <p>你好，兔子工厂！</p>
      </div>
    </div>
  );
}
```

**第三步**，`npm run dev` 启动——工具已自动出现在面板中。没有第三步以外的任何注册动作。

## 3. manifest.js 字段规范

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | ✅ | 工具唯一标识，**kebab-case 英文**（如 `image-convert`）。必须与目录名、后端 service 文件名一致 |
| `name` | `string` | ✅ | 显示名称，中文，建议 ≤ 6 字 |
| `icon` | `string` | ✅ | 单个 Emoji。卡片会自动套用分类色的圆角底 |
| `category` | `string` | ✅ | 分类 id，见下表。新增分类需编辑 `core/categories.js` |
| `load` | `() => import('./Panel.jsx')` | ✅ | 懒加载入口，**必须**是动态 `import()`，保持原样 |
| `desc` | `string` | ❌ | 一句话描述，卡片最多显示 2 行（CSS 截断） |
| `keywords` | `string[]` | ❌ | 搜索关键字。建议包含：英文名、中文名、同义词、常见文件扩展名 |
| `order` | `number` | ❌ | 排序权重，默认 500，越小越靠前。现有占用见下 |
| `accepts` | `{ files: string[] }` | ❌ | 声明可处理的文件扩展名（含点、全小写），用于悬浮球投喂智能匹配 |

**分类枚举**（`core/categories.js`）：

| --- | --- | --- |
| `file` | 文件 | 蓝 `#4E9CFF` |

| `fun` | 趣味 | 橙 `#FFA928` |
| `sec` | 安全 | 红 `#E5484D` |

**order 段位现状**（新工具请避开或按意图插入）：

## 4. Panel.jsx 前端规范

### 4.1 组件契约

- **默认导出一个 React 函数组件**（供 `React.lazy` 加载，模块内不要执行有副作用的顶层代码）。
- 可接收 props：`{ files }`。
  - `files?: string[]` —— 经「投喂/拖放匹配视图」进入时传入的**文件绝对路径数组**；直接从卡片点开时为 `undefined`。
  - **必须容忍 `files` 为空/未定义**，两种入口都要可用。

```jsx
export default function MyToolPanel({ files }) {
  React.useEffect(() => {
    if (files?.length) ingest(files);   // 投喂进入
  }, [files]);
  // …始终渲染完整界面
}
```

### 4.2 可用 API（`window.api.*`，preload 桥接）

| API | 签名 | 用途 |
| --- | --- | --- |
| `tool.run` | `(toolId, action, payload) => Promise<{ok, data?, error?}>` | 调用主进程服务 |
| `tool.onProgress` | `(cb: (p) => void) => void` | 订阅长任务进度（服务端经 `ctx.wm.panel.webContents.send('tool:progress', {...})` 推送） |
| `store.get` / `store.set` | `(key, def?)` / `(key, value)` | 轻量 JSON 持久化（落盘 `%APPDATA%/rabbit-factory/store.json`） |
| `dialog.openFile` | `(opts) => Promise<{canceled, filePaths}>` | 系统文件选择框（opts 为 Electron showOpenDialog options） |
| `dialog.saveFile` | `(opts) => Promise<{canceled, filePath}>` | 系统保存框 |
| `shell.showItem` | `(path) => void` | 在资源管理器中定位文件 |
| `shell.openExternal` | `(url) => void` | 用默认程序打开链接（仅 http(s)/magnet/ed2k/thunder/ftp 协议白名单） |
| `ball.getPathForFile` | `(File) => string` | 拖放事件中把 `e.dataTransfer.files[i]` 转为绝对路径（webUtils 封装） |
| `panel.hide` | `() => void` | 收起面板 |

安全模型：渲染进程**无 Node 能力**（contextIsolation 开启、nodeIntegration 关闭），一切系统能力都必须走 `tool.run` 后端。

### 4.3 文件类工具的交互约定

参照 `image-convert` / `audio-convert` 的成熟模式：

1. **空状态**：一个大的虚线拖放区（`.ic-drop`），点击打开文件选择框，同时支持拖放：

```jsx
<div
  className="ic-drop"
  onClick={pick}
  onDragOver={(e) => e.preventDefault()}
  onDrop={(e) => {
    e.preventDefault();
    e.stopPropagation();                    // 防止冒泡触发面板级投喂
    const paths = [...e.dataTransfer.files]
      .map((f) => window.api.ball.getPathForFile(f))
      .filter(Boolean);
    addFiles(paths);
  }}
>
```

2. **选项区**：格式/参数用分段按钮（`.seg` / `.seg-btn`），数值用 `range`。
3. **文件列表**：每行一个 `.ic-item`，状态文案放在 `.ic-info` 元素内（见 §7 自动化测试约定）。
4. **输出约定**：默认输出到**源文件所在目录**；目标路径与源相同时追加 `-converted` 后缀；完成后点击文件名触发 `shell.showItem` 定位。
5. **主操作按钮**必须使用 `btn primary` 类（见 §7）。

### 4.4 样式规范

- **必须复用设计令牌与既有组件类**，禁止硬编码颜色（保持主题一致）：

| 类别 | 可用资源 |
| --- | --- |
| CSS 变量 | `--accent` `--accent-deep` `--accent-soft` `--ink` `--ink-2` `--ink-3` `--bg` `--bg-soft` `--line` `--radius` |
| 按钮 | `.btn.primary` `.btn.ghost` |
| 分段选择 | `.seg` `.seg.wrap` `.seg-btn(.on)` |
| 文件工具骨架 | `.ic-panel` `.ic-drop(-icon/-text/-sub)` `.ic-controls` `.ic-ctrl` `.ic-list` `.ic-item(.ok/.err/.running)` `.ic-thumb` `.ic-meta` `.ic-name` `.ic-info` `.ic-del` `.ic-actions` `.ic-note` |
| 空状态 | `.empty-state(.small)` `.empty-face` |
| 其他 | `.copy-btn` `.todo-*`（可参考其写法） |

- 新工具的私有样式**追加到 `src/renderer/src/app.css` 末尾**，统一加注释分区头 `/* ============ <工具名> ============ */`，选择器以工具 id 为前缀（如 `.qr-` `.pomo-`）避免冲突。
- 可用区域为固定尺寸 480×680 面板中的 `.tool-body`（自动出滚动条），内容超高即可滚动，无需自己处理。
- 动效遵循全局节奏：hover 位移 ≤ 3px、时长 0.15–0.2s、缓动 `cubic-bezier(.2,.8,.3,1.2)`。
- 中文字体栈已全局设定，不要另行指定。

## 5. 后端 Service 规范（`src/main/services/<tool-id>.js`）

```js
'use strict';
const fs = require('fs');

module.exports = {
  id: 'my-tool',                          // 必须与文件名、manifest.id 一致
  async run(action, payload, ctx) {       // async 可选；ctx: { wm } 窗口管理器
    switch (action) {
      case 'readFile':
        return fs.readFileSync(payload.path).toString('base64');
      default:
        throw new Error(`未知操作: ${action}`);   // 抛错会自动变成 { ok:false, error }
    }
  },
};
```

规则：

1. **返回值必须可 JSON 序列化**（Buffer 要转 base64/string）。
2. 用 `action` 字符串区分操作，用 `throw` 表达失败——注册中心已统一包装。
3. `ctx.wm` 可访问窗口管理器；若服务会弹出**模态系统对话框**，前后置 `ctx.wm._panelBusy = true/false`，防止面板因失焦被自动收起（`ipc.js` 中 dialog 处理器已内置此逻辑，可直接让前端走 `dialog:*` 通道）。
4. 大文件/二进制经 **base64 过桥**（面板内文件 ≤ 几 MB 时简单可靠）；超大文件建议后端直接操作路径，只回传结果。
5. 长耗时任务：直接 `await` 串行执行即可（面板有 busy 态）；进度上报暂无通道，状态文案用「转换中…」占位。

### 原生二进制依赖（重要）

如需携带原生可执行文件（如 ffmpeg），遵循以下模式，否则打包后必然 ENOENT：

1. 选用提供静态二进制的 npm 包（如 `ffmpeg-static`），加入 `dependencies`；
2. 在 `electron-builder.yml` 的 `asarUnpack` 中声明该包；
3. 服务层对路径做 asar 替换（ffmpeg-static 5.x 已不再自动处理）：

```js
let binPath = require('ffmpeg-static');
if (binPath && binPath.includes('app.asar')) {
  binPath = binPath.replace('app.asar', 'app.asar.unpacked');
}
const proc = require('child_process').spawn(binPath, args, { windowsHide: true });
```

优先选择纯 JS 依赖（如二维码用的 `qrcode`），可完全规避此问题。

### WASM / 外部脚本依赖（CSP）

渲染进程受 `index.html` 的 CSP 保护。使用 WASM 引擎（如 OCR 的 tesseract）或从 CDN 动态加载脚本时：

1. WASM 编译需要在 CSP `script-src` 中包含 **`'wasm-unsafe-eval'`**（缺失时 WASM 初始化会静默挂起，不报错——OCR 工具曾因此排查良久）；
2. CDN 脚本域名需加入 `script-src` 白名单（现有：cdn.jsdelivr.net / unpkg / npm.elemecdn.com）；
3. 外部请求需 `connect-src https:`（已配置）；Web Worker 需 `worker-src 'self' blob:`（已配置）。

**长耗时任务的进度推送**：服务端在 `run()` 内通过 `ctx.wm.panel.webContents.send('tool:progress', { toolId, ... })` 推送，前端用 `window.api.tool.onProgress(cb)` 订阅（参考 zip-pass 工具）。

## 6. 投喂（拖放智能匹配）集成

1. 在 manifest 声明 `accepts.files`，投喂时注册中心自动按扩展名匹配，进入「这些工具可以处理它们」选择视图；
2. 用户选中你的工具后，`Panel.jsx` 收到 `files` props —— 按 §4.1 消费；
3. 匹配是「任一文件命中即匹配」；扩展名**必须全小写且带点**；
4. 面板本身也接受拖放（`PanelApp` 根节点已处理），工具内部拖放区记得 `e.stopPropagation()` 防止重复进入匹配视图。

## 7. 自动化验证约定（Loop 自检协议）

工具必须兼容项目自带的验证流程（`npm run verify` 及 env 组合），这也是 CI 未来的抓手：

| 约定 | 原因 |
| --- | --- |
| **主操作按钮使用 `.btn.primary`** | `VERIFY_FUNC=1` 会自动点击第一个 `.btn.primary` 触发真实转换 |
| **逐文件状态文案写入 `.ic-item .ic-info`** | `VERIFY_FUNC=1` 读取这些元素断言结果（如 `✓ 已输出 xxx`） |
| 文件类工具支持 `files` props 注入 | `VERIFY_FILES=A\|B` 经 `__openTool` 注入，模拟投喂路径 |

**验证矩阵**（对 `electron .` 设环境变量）：

```
VERIFY=1                      启用自检模式（跑完自动退出；结果同时落盘 .verify/report.json）
VERIFY_DOM=1                  DOM 断言（ball/panel + 逐工具布局溢出审计）
VERIFY_TOOL=a,b,c             依次打开指定工具并截图 03-tool-<id>.png
VERIFY_FILES=p1|p2            与 VERIFY_TOOL 连用，注入文件路径
VERIFY_FUNC=1                 对工具执行端到端功能测试（自动点 .btn.primary，读状态行）
VERIFY_WAIT=<ms>              功能测试等待时长（默认 1800ms；OCR 等慢任务可加大）
VERIFY_EXPR=<js>              功能测试前在面板执行的任意 JS（切换模式/预置状态）
VERIFY_PICK=<路径>            模拟面板打开时投喂文件，断言匹配视图
VERIFY_CLICK=<卡片名>         真实系统级鼠标事件点击工具卡片并断言视图切换
VERIFY_POSE=hover|press|excited|drag   悬浮球指定姿态截图
```

示例——新工具全量自检：

```bash
npm run build && VERIFY=1 VERIFY_DOM=1 VERIFY_TOOL=my-tool npm start
# 或直接：
VERIFY=1 VERIFY_DOM=1 VERIFY_TOOL=my-tool ./node_modules/.bin/electron .
```

截图输出在 `.verify/`。**提交前要求**：布局审计无 `OUT:` 越界项、功能测试输出 `✓`、截图人工复核无溢出/重叠。

## 8. 完整示例：带后端的工具

`tools/qrcode` 中保存 PNG 借用了 `image-convert` 的 writeFile 动作——**工具间可以复用彼此的 service 动作**，只要语义匹配：

```jsx
// tools/qrcode/Panel.jsx（节选）
const res = await window.api.tool.run('image-convert', 'writeFile', {
  dir, name, base64: url.split(',')[1],
});
if (res.ok) window.api.shell.showItem(res.data);
```

新写一个带后端的工具时，推荐先翻看 `services/` 下已有动作，避免重复造轮子。

## 9. 持久化键位规范

`store` 是全局单文件 JSON，键名即命名空间：

- 键名用 **camelCase**，以工具语义命名：`todos`、`pomodoroCount`、`ballPos`（系统占用）；
- 单工具多个数据合并进一个键（对象/数组），避免碎片化；
- 写入用防抖（参考 todo 工具：变更后 250ms 再 `set`），避免高频落盘。

## 11. 常见问题

| 现象 | 原因 |
| --- | --- |
| 面板里看不到新工具 | manifest 忘了 `export default`；目录层级不对（必须在 `tools/<id>/manifest.js`）；`load` 写成了静态 import |
| 搜不到 | keywords 未覆盖；搜索是 name/desc/keywords/id 的小写包含匹配 |
| 投喂不匹配 | `accepts.files` 扩展名缺点或大写；文件无扩展名 |
| `tool.run` 返回 `未找到工具服务` | service 文件名与 `id` 不一致，或导出缺 `id` 字段 |
| 打包后报 ENOENT（二进制） | 未 asarUnpack / 未做路径替换（§5.5） |
| 弹文件框后面板消失了 | 未走 `dialog:*` 通道自制了模态弹窗；改用 `ctx.wm._panelBusy` 包裹 |
